# Architecture — SpendSync

> Generated by codebase-mapper on 2026-10-16

## Overview
SpendSync is a personal expense tracking system with an Android native client (`app/`) talking to a Next.js + Better Auth + Postgres API (`backend/`). The Android client features an AI-powered assistant with tools, streaming responses, offline fallback, amount privacy masking, and voice interaction capabilities (dictation, voice mode, and read-aloud).

## Components

### Assistant Screen (`app/src/main/java/com/example/spendsync/ui/assistant/AssistantScreen.kt`)
- **Purpose:** Primary chat interface rendering messages, proposal cards, bill cards, streaming indicators, and voice mode triggers.
- **Dependencies:** `AssistantViewModel`, `VoiceController`, `SessionDataStore`, `AmountVisibilityState`.
- **Dependents:** Main navigation pager, notification shortcuts.

### Voice Layer (`app/src/main/java/com/example/spendsync/voice/`)
- **Purpose:** On-device voice input and output orchestration.
  - `VoiceSession.kt`: Pure state machine (`VoicePhase`: Off, Listening, Thinking, Speaking, Paused).
  - `SpeechInput.kt`: Wraps Android `SpeechRecognizer` for partial and final transcription and audio RMS levels.
  - `SpeechOutput.kt`: Wraps Android `TextToSpeech` with utterance progress tracking, voice selection, and language fallback.
  - `SpokenText.kt`: Incremental sentence chunker (`SentenceFeed`) and privacy-safe speech sanitizer with PIN amount masking.
  - `VoicePrefs.kt`: Device-local voice configuration (listening language, preferred voice, speech rate, continuous listening).

### Voice UI & Motion (`app/src/main/java/com/example/spendsync/ui/assistant/VoicePanel.kt`)
- **Purpose:** Visual presentation and controller lifecycle management for voice mode.
- **Motion Integration:** Integrated with `ui/theme/Motion.kt` (`LocalMotion`, `MotionPrefs`) to respect global animation toggles and Android accessibility settings.

## Data Flow
1. **User Voice Input:**
   `SpeechInput` detects microphone audio → emits `onLevel` RMS decibels and `onPartial` transcripts → emits `onFinal` when speech pauses.
2. **Turn State Machine:**
   `VoiceEvent.Heard` transitions `VoicePhase` from `Listening` to `Thinking`.
3. **Model Processing:**
   `AssistantViewModel.send()` posts to `/api/assistant/chat` via SSE.
4. **Streaming Response to Speech:**
   Incoming SSE tokens are fed into `SentenceFeed` → sanitized with `toSpeech()` (masking sensitive financial figures) → queued sentence-by-sentence into `SpeechOutput`.
5. **Speech Playback:**
   First sentence starts playback → triggers `VoiceEvent.Speaking`.
6. **Completion / Continuous Loop:**
   `UtteranceProgressListener` detects queue completion → if `keepListening` is true, automatically transitions back to `VoicePhase.Listening` for continuous hands-free dialogue.

## Integration Points
| External Service | Type | Purpose |
|------------------|------|---------|
| Android `SpeechRecognizer` | Platform API | On-device / cloud speech-to-text with streaming partials |
| Android `TextToSpeech` | Platform API | On-device synthesis with multi-voice support |
| `/api/assistant/chat` | HTTP SSE | LLM inference, function calling, tool execution |
| Room DB (`outbox`, `cached_responses`) | SQLite | Offline-first transaction and assistant cache |

## Conventions
- **UI Components:** Compose Material 3 with standard wrapper components (`AppButton`, `AppIconButton`, `AppDialog`).
- **Motion:** `LocalMotion.current.enabled(MotionKind.Transitions)` with `animate*AsState` and `rememberInfiniteTransition`.
- **Internationalization:** All strings externalized to `strings*.xml` across 5 supported languages (en, hi, es, fr, de).
- **Privacy First:** Amounts masked behind PIN before visual rendering and before TTS speech queueing.
